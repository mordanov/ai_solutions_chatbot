# Implementation Plan: Approved Reservation Storage Service

**Branch**: `003-mcp-reservation-storage` | **Date**: 2026-08-12 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/003-mcp-reservation-storage/spec.md`

## Summary

When an administrator approves a parking reservation, the system must persistently record that approval to a text file in the format `Name | Car Number | Reservation Period | Approval Time`. This is implemented as a dedicated **MCP (Model Context Protocol) server** — a subprocess that the existing FastAPI application communicates with via the standard MCP stdio transport. The approve endpoint spawns the server, calls the `write_reservation_record` tool, and the server appends the record to a configured file path. Security is provided by process isolation (stdio — not network-accessible) plus the existing admin-token authentication on the API layer.

## Module Responsibilities

### `storage/writer.py` — `ReservationWriter`

Pure file I/O, no MCP dependency. The only module that touches the filesystem.

```python
class ReservationWriter:
    def __init__(self, file_path: str) -> None: ...
    def write(self, name: str, car_number: str, reservation_period: str, approval_time: str) -> str:
        """Appends one pipe-delimited line. Returns the written line. Thread-safe via fcntl.LOCK_EX."""
```

- Sanitizes ` | ` → ` / ` in all input fields before formatting.
- Creates parent directories if they don't exist.
- Returns the exact line written (for logging and MCP response).

### `storage/server.py` — MCP Server

Entry point: `python -m chatbot.storage.server`

```python
from mcp.server import Server
from mcp.server.stdio import stdio_server

server = Server("reservation-storage")

@server.list_tools()
async def list_tools() -> list[Tool]: ...

@server.call_tool()
async def call_tool(name: str, arguments: dict) -> list[TextContent]: ...

async def main():
    async with stdio_server() as (read_stream, write_stream):
        await server.run(read_stream, write_stream, ...)

if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

- Reads `RESERVATIONS_FILE_PATH` from environment at startup.
- Delegates to `ReservationWriter.write(...)`.
- Returns `isError: true` with a descriptive message on any exception.

### `storage/client.py` — `ReservationStorageClient`

```python
class ReservationStorageClient:
    async def write_record(
        self,
        name: str,
        car_number: str,
        reservation_period: str,
        approval_time: str,
    ) -> None:
        """Spawns the MCP server subprocess and calls write_reservation_record."""
```

- Uses `StdioServerParameters` from the `mcp` SDK to launch the server.
- Calls `session.call_tool("write_reservation_record", {...})`.
- Raises `RuntimeError` if the server returns `isError: true`.
- Raises `RuntimeError` on subprocess or protocol failure.
- The subprocess is spawned fresh per call (see research Decision 1: no long-lived subprocess needed).

### `api/main.py` — `approve_reservation` modification

```python
@app.post("/admin/reservation/{request_id}/approve", status_code=204)
async def approve_reservation(request_id: str, _=Depends(_require_admin)) -> None:
    from chatbot.approval.service import ApprovalService
    from chatbot.approval.store import pending_store
    from chatbot.storage.client import ReservationStorageClient

    req = pending_store.get_by_request_id(request_id)
    if req is None:
        raise HTTPException(404, "Reservation request not found")
    try:
        ApprovalService().record_decision(request_id, "approved")
    except ValueError as exc:
        raise HTTPException(409, "Reservation request is no longer actionable") from exc

    # Write to MCP storage server
    from datetime import UTC, datetime
    approval_time = datetime.now(UTC).strftime("%Y-%m-%d %H:%M")
    period = f"{req.start_datetime} → {req.end_datetime}"
    try:
        await ReservationStorageClient().write_record(
            name=f"{req.first_name} {req.surname}",
            car_number=req.license_plate,
            reservation_period=period,
            approval_time=approval_time,
        )
    except Exception as exc:
        logger.error("Storage write failed for request %s: %s", request_id, exc)
        # Do NOT rollback the approval — user still gets their notification.
        # Log the failure; the admin can re-check the storage file manually.
```

Note: Storage write failure is logged but does not roll back the approval decision. The in-memory store is the primary record; the file is an audit log. This design decision avoids a two-phase-commit problem at the cost of the file potentially missing a record on failure. If stronger guarantees are required, a retry queue would be added in a later stage.
